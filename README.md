# gwarancje
Gwarancje.PRO

## Hosting

Strona jest serwowana przez Cloudflare Workers (worker `gwarancje`, statyczne pliki z katalogu
`public/`, konfiguracja w `wrangler.jsonc`). Domyślna obsługa plików HTML (`auto-trailing-slash`)
serwuje `public/blog.html` pod adresem `/blog` i przekierowuje `/blog.html` → `/blog`, dlatego
wszystkie adresy w linkach, canonical, sitemapie i RSS są **bez rozszerzenia `.html`**
(`/blog`, `/blog/<slug>`, `/polityka-prywatnosci`). Lokalny `python3 -m http.server` nie zna
tej reguły — do podglądu lokalnego otwieraj pliki z `.html`.

## Blog statyczny

Artykuły bloga są przechowywane w Supabase (tabela `aura_articles`, platforma `Gwarancje.pro`),
ale na stronie publikowane są jako zwykłe pliki HTML. Dzięki temu Google, Bing i roboty
silników AI (OAI-SearchBot, ClaudeBot, PerplexityBot) widzą pełną treść bez wykonywania JavaScriptu,
a każdy artykuł ma własny adres, tytuł, opis, canonical, Open Graph i JSON-LD `BlogPosting`.

### Jak artykuł trafia z panelu na stronę

1. W `/admin.html` zapisz artykuł ze statusem **opublikowany** (status `published`).
2. GitHub Action **Build blog** (`.github/workflows/build-blog.yml`) uruchamia się co 6 godzin,
   a także po każdym pushu do `main`, który zmienia `scripts/build-blog.mjs` lub sam workflow.
   Żeby nie czekać, uruchom go ręcznie: zakładka *Actions* → *Build blog* → *Run workflow*.
   Harmonogram działa dopiero, gdy workflow jest na gałęzi `main`.
3. Skrypt `scripts/build-blog.mjs` pobiera opublikowane artykuły i generuje:
   - `public/blog/<slug>.html` — strona każdego artykułu (adres publiczny `/blog/<slug>`),
   - `public/blog/index.json` — mapa `id → slug` dla starych linków `blog.html#<uuid>`,
   - `public/blog/feed.xml` — kanał RSS,
   - `public/sitemap.xml` — mapa strony (strona główna, `/blog`, artykuły, strony prawne jeśli istnieją),
   - listę artykułów i JSON-LD w `public/blog.html` (bloki między `<!-- GEN:BLOG-LIST:START/END -->`
     i `<!-- GEN:BLOG-SCHEMA:START/END -->`),
   - trzy najnowsze wpisy w karcie „Aktualności” w `public/index.html` (blok `<!-- GEN:HERO-BLOG:START/END -->`, jeśli znaczniki istnieją).
4. Jeśli coś się zmieniło, Action robi commit `chore(blog): regenerate static articles` i push do `main`,
   co uruchamia deploy strony.

Artykuł wycofany z publikacji (szkic lub usunięty z platformy `Gwarancje.pro`) znika przy kolejnym
uruchomieniu — skrypt usuwa tylko pliki, które sam wygenerował (oznaczone komentarzem
`<!-- generated by scripts/build-blog.mjs -->`). Bloki między znacznikami `GEN:*` są nadpisywane
przy każdym uruchomieniu, więc nie edytuj ich ręcznie.

Zabezpieczenie: gdy Supabase zwróci **0** opublikowanych artykułów, a w `public/blog/` są już
wygenerowane strony, skrypt kończy się błędem i niczego nie kasuje (najczęstsza przyczyna to zmiana
polityk RLS lub nazwy platformy, nie świadome wycofanie bloga). Świadome opróżnienie bloga:
`ALLOW_EMPTY=1 node scripts/build-blog.mjs`.

Tagi zapisane w bazie jako hashtagi (`#gwarancjawadialna`) są przy budowaniu zamieniane na czytelne
etykiety ze słownika `TAG_LABELS` w skrypcie; nieznane zostają bez zmian. Akapity złożone wyłącznie
z hashtagów są pomijane na stronie, a pierwszy obraz bez `alt` dostaje tytuł artykułu.

### Uruchomienie lokalne

Wymagany Node 22, bez instalowania zależności:

```bash
node scripts/build-blog.mjs
```

Opcjonalne zmienne środowiskowe:

- `BUILD_DATE=RRRR-MM-DD` — data „dzisiaj” (domyślnie bieżąca): `lastmod` w sitemapie i `lastBuildDate`
  w RSS, gdy nie ma artykułów, oraz data artykułu, który nie ma `published_at` ani `created_at`,
- `SUPABASE_ANON_KEY` — nadpisuje publiczny klucz anon wpisany w skrypcie,
- `ALLOW_EMPTY=1` — pozwala wygenerować pusty blog (patrz wyżej).

Skrypt jest idempotentny: drugie uruchomienie bez zmian w bazie nie modyfikuje żadnego pliku.
Jeśli Supabase nie odpowiada, skrypt kończy się błędem i nie rusza istniejących plików.

### Assety graficzne

`scripts/build-assets.mjs` (Playwright + Chromium) renderuje `public/logo.png`, `public/og-image.png`,
ikony (`favicon.ico`, `apple-touch-icon.png`, `icon-192.png`, `icon-512.png`). `favicon.svg`
i `site.webmanifest` są ręczne. Uruchamiaj tylko przy zmianie znaku graficznego.
